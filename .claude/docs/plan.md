# План UpdateManager

Текущая версия — **2.1.0** (тег `v2.1.0`, 2026-10-28). Схема версий — SemVer из трёх чисел:
новая возможность → minor, иначе patch. Каждый выпуск — тег `vX.Y.Z` (см. `CLAUDE.md`).

### Удаление версий — что осталось за рамками 2.2

- Удалённые выпуски не показываются архивом — просто исчезают (номера остальных не сдвигаются).
- Экономит только диск проекта; `Output/` и сервер не уменьшаются (чистка старых инкрементальных — отдельный вопрос:
  тогда очень старые клиенты пойдут через repair). Движок: после удаления старых `Versions/` инкрементальные патчи
  в `Output/IncrementalPatch` остаются, клиенты обновляются по цепочке (проверено 2026-10-28).
- Откат Android — только новой записью версии из старой папки билда (сборка вне проекта).

## Отказались

- **Обновление ссылок в готовом `VersionInfo.info` (`PatchUpdater`, шаг 7 плана 1.x).** Нужно было бы,
  если `BaseDownloadURL` нельзя задать при сборке. Вместо этого сборка блокируется при пустом адресе,
  итоговый адрес виден в настройках, а «Проверить» ловит неверный. Вернуться, если появится реальный случай.
- **Анимация заливки блока этапа.** Каталог пересобирается после каждого действия — переход цвета не
  сыграл бы без переделки модели выпуска, а для инструмента, который открывают раз в несколько недель,
  это не окупается. Правило «без движения» — `DESIGN.md` (The Still Catalog Rule).
