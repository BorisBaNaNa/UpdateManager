## 2.0.0.0

UpdateManager переписан на **Avalonia / .NET 10** с новым интерфейсом. Возможности 1.x сохранены. 2.0 ставится отдельно и не обновляет 1.x. Ветка 1.x — `v1`, тег `v1.0.3`.

### Новая платформа

- **Avalonia 12 / .NET 10**, сборка self-contained для win-x64: .NET устанавливать не нужно.
- Логика вынесена в отдельный слой `UpdateManager.Core`, интерфейс построен на MVVM. Добавлены юнит-тесты и сквозной прогон движка SimplePatchTool: сборка → подпись → проверка → обновление клиента.

### Каталог выпусков

- **Стартовый экран**: последний проект крупно, с его этапами и кнопкой «Открыть», ниже — список недавних. Недавний проект, у которого пропала папка, приглушён, его можно убрать из списка.
- **Каталог выпусков**: каждая версия — запись с этапами **Билд → Патч → Доставка → Проверка**. Пройденный этап залит цветом, ещё не пройденный — контур, провал — красный контур с причиной. Состояние также написано словами: «№ 5 · проверка не прошла».
- **Одна главная кнопка** называет следующий шаг: «Создать патч», «Доставить», «Проверить».
- **Повтор этапов**: блоки последнего выпуска нажимаются. Можно пересобрать ту же версию, доставить или проверить снова. Следующие этапы при этом сбрасываются: пересобранный патч считается не доставленным и не проверенным.
- **Новый билд** в папке-источнике (версия новее собранных) появляется отдельной записью «новый».
- По каждой версии запоминаются даты сборки патча и доставки, а также итог проверки.

### Сборка, доставка, проверка

- В настройках проекта сразу виден итоговый `BaseDownloadURL`: «Клиенты будут качать патч с …». Если адрес пуст — предупреждение.
- Окно операции показывает состояние словами («Выполняется · 42 %», «Готово», «Завершилось с ошибкой»), а причину ошибки — над журналом, а не в его конце.
- **Доставку** можно настроить заранее, без самой доставки: «Доставка → Настроить…».
- **FTP**: понятные сообщения об ошибках вместо «See InnerException», обзор папок сервера, неотслеживаемые файлы на сервере при заливке не трогаются.
- **Проверка** скачивает патч так же, как это делает клиент. Итог записывается в блок «Проверка».

### Самообновление

- UpdateManager обновляет сам себя тем же движком: тихая проверка при запуске и пункт «Справка → Проверить обновления…».
- Билд самого UpdateManager распознаётся автоматически. Программа предлагает пресет: self-patching, `BaseDownloadURL`, `IgnoredPaths`.
- Встроенный self-patcher лежит в `SPPatcher\` — там же, куда его кладёт движок. Поэтому только что установленная версия ничего не докачивает при первой проверке.
- Сервер обновлений: `https://updates.borealis-soft-home.duckdns.org:51943/`.

### Оформление

- Новый дизайн всех окон: матовый фон, тонкие линии, прямые углы. Цвет используется только для этапов выпуска.
- Светлая, тёмная тема и «как в Windows».
- Шрифт интерфейса — **Golos Text** (лицензия OFL, файл лицензии — в `licenses\`).

### Прочее

- Выпуск собирается скриптом `scripts/release.ps1`: тесты, версия, publish в `Release/`, version holder `UpdateManager_vers.sptv`.
- Версия инструмента — **2.0.0.0**.
