# Платформа Android — дизайн

Статус: согласовано 2026-10-28, реализовано (выйдет в **2.1.0**).
Источник требований: манифест владельца «UpdateManager: подпись файлов по маске» (Android-выпуск AlmaProfile).

Уточнение после выпуска 2.3.0: исходные решения о ручном вводе версии ниже описывают 2.1.
В отдельном Android-проекте теперь читается `versionName` из JSON-манифестов сборки; при отсутствии
однозначной допустимой версии остаётся ручной ввод. При обеих платформах версия берётся из Windows
(начиная с 2.2). Актуальное поведение — [README, Android](../../../README.md#android).
Разбор самого APK по-прежнему не выполняется.

## Цель

Проект обновлений выпускает две **включаемые** платформы: Windows (патч движка + подпись манифестов) и Android
(без патчей: подмена apk и подпись файлов по маске). Выпустить можно обе сразу или одну. UpdateManager остаётся
универсальным: не знает, что за файлы подписывает и что в них.

## Решения

| Вопрос | Решение |
|---|---|
| Где живёт Android | Платформа в том же проекте: общие RSA-ключ (`private.key`/`public.key` в корне), способ доставки и реквизиты FTP |
| Включение | Флажки «Windows» и «Android» в настройках проекта (мета). Выключенная платформа не показывается в каталоге |
| Этапы Android | Билд (папка, вход извне) → **Файлы** (подпись по маске) → Доставка → Проверка |
| Версия Android | Спрашивается при подписи (начало выкладки), подсказка — версия последнего выпуска проекта. Совпала с Windows-версией — одна запись каталога с двумя полосами |
| Подпись | Маски (glob, относительно папки билда, по одной в строке). RSA, SHA-256, PKCS#1 v1.5 по сырым байтам; `<файл>.sig` рядом — base64, UTF-8 без BOM, без перевода строки; самопроверка `public.key`; маска ничего не нашла — ошибка. Ключ — RSA-XML проекта |
| Что выкладывается | Все файлы папки билда, кроме масок «Не выкладывать» и `.sig`, не созданных этой подписью (чужой/устаревший `.sig` не уедет) |
| Куда | Папка канала (по умолчанию `AndroidPatch`) внутри папки Windows-патча: FTP — корень патчей + директория загрузки + канал; папка — путь доставки + канал. Публичный адрес — `BaseDownloadURL` + канал |
| Как | Атомарно: заливка во временную папку `<канал>_new`, подмена переименованием. Подписанные файлы и `.sig` появляются вместе с остальными — разом |
| Старое на сервере | Удаляется после успешной отправки — и у Android, и у Windows. Прежнее сохранение «чужих» файлов (костыль под ручной AndroidPatch) убрано. Исключение: Windows-доставка не трогает папку канала Android — она наша и выкладывается отдельно |
| Проверка Android | По публичному адресу канала скачать каждый выложенный файл и `.sig`: байты совпадают с локальными, подпись сходится с `public.key` |
| Повтор этапов | Как у Windows: повтор стирает записи следующих этапов этой платформы и версии |

## Мета (`updatemanager.project.xml`)

- `<Platforms windows="true" android="false"/>`.
- `<Android buildSource="…" channel="AndroidPatch"><Sign>маска</Sign>…<Exclude>маска</Exclude>…</Android>`.
- По версиям: `<AndroidSigned>`, `<AndroidDelivered>` (как `PatchedVersions`), `<AndroidVerified>` (как `VerifiedVersions`).
- Старые проекты: Windows включён, Android выключен.

## Настройки AlmaProfile (пример)

| Что | Значение |
|---|---|
| Папка билда Android | `D:\AvaloniaProjects\AlmaProfile\build\android\` |
| Маска подписи | `latest.json` |
| Не выкладывать | `AlmaProfile-x86_64.apk` |
| Канал | `AndroidPatch` (внутри `…/06a0…/`) |

Итог на сервере: `AndroidPatch/AlmaProfile.apk`, `latest.json`, `latest.json.sig`.
Проверка совместимости: подпись PKCS#1 v1.5 детерминирована — `latest.json.sig` от сборки 0.9.23 должен совпасть
байт в байт с подписью UpdateManager тем же ключом.

## Не входит

- Подпись самого APK (keystore) — забота сборки проекта.
- Разбор `latest.json`/apk (версия не читается из файлов).
