# Выпуск UpdateManager

Прочитай `AGENTS.md`, раздел о выпуске в `.claude/CLAUDE.md` и весь `scripts/release.ps1` до запуска. Источник поведения — скрипт; подробная общая процедура остаётся в `.claude/CLAUDE.md`.

1. Установи текущую версию из `Directory.Build.props`, ветку и dirty state. Новая возможность — minor, иначе patch; явная версия пользователя имеет приоритет. До сборки подготовь `docs/releases/X.Y.Z.md`: этот текст вшивается в приложение и идёт в GitHub Release.
2. Выполни `powershell.exe -ExecutionPolicy Bypass -File scripts/release.ps1 patch|minor|major` либо `-To X.Y.Z` / `-NoBump` по задаче. Скрипт прогоняет тесты до изменения версии, очищает `Release/`, делает self-contained publish и проверяет FileVersion, version holder и `Release/SPPatcher/SelfPatcher.exe`. `-DryRun` только показывает план. Не пропускай тесты без уже успешного прогона именно проверяемого кода.
3. Пользователь проверяет билд и ставит патч. Только по его слову создай коммит подъёма версии и аннотированный тег `vX.Y.Z` на коммите, из которого собран Release. Это специальная граница выпуска; обычные тематические коммиты делаются самостоятельно.
4. Пользователь сам отправляет main и тег. Не пушь и не предлагай push. `-Publish` — отдельное внешнее действие по запросу публикации: сверяет локальный/удалённый тег и билд, создаёт GitHub Release через gh с архивом. Наличие скрипта не разрешает публикацию во время аудита или миграции знаний.
5. Сохраняй `release.ps1` в UTF-8 с BOM. Не включай ключи, реквизиты и локальный Release в Git. В отчёте различай сборку, проверку пользователем, коммит/тег и публикацию.
